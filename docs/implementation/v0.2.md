# v0.2 closed-loop editing status

Implemented:

- explicit `EVALUATING`, `REFINING`, and `ACCEPTED` states;
- one checkpoint, read-back, render, and evaluation artifact per iteration;
- evaluator rationale and usage accounting in `iteration-report.json`;
- bounded iteration count, low-confidence escalation, repeated render/plan stall
  detection, and terminal `ACCEPTED` or `REVIEW_REQUIRED` behavior;
- checkpoint-only rollback metadata without claiming Lightroom true undo;
- v0.1 artifact aliases for backward compatibility;
- local scripted/mock evaluators plus an opt-in `OpenAIEditEvaluator` with a
  schema-validated response. A cloud evaluator is refused unless
  `--allow-cloud-preview` is present, including on `resume`, and receives a new
  sanitized per-iteration JPEG rather than the backend render path.

Automated evidence on 2026-08-12:

- accept on first evaluation;
- refine, re-render, then accept;
- repeated refinement escalates instead of silently retrying;
- cloud evaluation is rejected before the evaluator/backend is called without
  explicit consent, while an allowed fake receives only the sanitized session
  copy;
- full TypeScript, lint, test, and build gates pass (see `WORKLOG.md`).

Not verified: a live OpenAI evaluator request, live Lightroom mutation/render,
evaluator-to-human agreement, and human inspection of a Lightroom-produced
result. Use a non-critical test photo and explicit approval before those checks.
