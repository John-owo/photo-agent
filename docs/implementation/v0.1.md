# v0.1 implementation status

The v0.1 implementation hardens the v0.1-alpha single-photo workflow without
introducing culling, clustering, batch orchestration, or Style Memory.

Implemented in this milestone:

- stale-aware mutation locks with PID, session, backend, and creation metadata;
- `recover` CLI flow that reads back possible backend state after interruption,
  never retries a Develop mutation automatically, reuses a persisted Workflow
  Copy identity for exact read-back, reconciles unresolved Copy creation through
  an explicitly read-only backend query with the same operation ID after Master
  read-back, and emits non-overwriting recovery evidence;
- XMP fallback for the supported global develop settings, with atomic create-only
  writes that refuse to overwrite an existing sidecar;
- reproducible JSON intent/current-settings fixtures and an explicit XMP example;
- thin Codex handoff skill documentation;
- lazy, identity-verified Workflow Copy isolation for every executable
  single-photo apply, with Master/Copy inheritance checks and Copy-only
  checkpoint, mutation, read-back, and render targeting;
- durable per-iteration operation IDs, target identity, requested settings, and
  Checkpoint evidence written before non-idempotent Develop work;
- regression tests for lock ownership, recovery, and XMP safety.

Still manual before a v0.1 release:

- inspect the clean-clone CI run for the repository/ref being released; the
  smoke command is now part of CI (`npm run example`);
- Lightroom Classic + MCP end-to-end run on a non-critical photo;
- human inspection of the resulting render;
- `.lrtemplate` round-trip validation if preset export is advertised as stable.

The live and human gates are recorded separately in the
[T09 clean-clone and live-evidence pack](../acceptance/t09-clean-clone-and-live-evidence.md).
