# photo-agent v0.1 → v0.3 實作方向

本文件把 `ROADMAP.md` 轉成可驗收的開發順序。版本號代表可驗收的能力，
不是單純增加功能數量。

## 目前判定

目前基線是 `v0.1-alpha`：單張明確 RAW／preview 配對、Codex-local handoff、
normalized edit plan、Lightroom adapter、session manifest 與 mock 測試已存在。
目前程式已補上 XMP fallback、lock recovery 與公開範例，但仍不能宣稱 v0.1 release
完成，因為真實 Lightroom E2E、人工 render 檢查、clean-clone CI 與 XMP 匯入驗證仍需完成。

## 進入 v0.2 前：完成 v0.1

### 1. Repository 與可重現驗證

- 建立正式 `main`，並讓 push／PR CI 覆蓋目前的開發分支。
- 乾淨 clone 後執行 `npm.cmd run check`、`lint`、`test`、`build`；變更檔案需通過 Prettier。
- 補 CHANGELOG、Architecture、Privacy、Security、Contributing 與 v0.1 release checklist。

### 2. 單張 Lightroom E2E

- 使用非關鍵測試照片，驗證配對、checkpoint、套用、read-back、session render。
- 人工檢查 render；確認來源 RAW、preview、sidecar 與交付資料夾沒有被覆寫。
- `.lrtemplate` round-trip 在宣稱 preset 穩定前必須另外通過人工測試。

### 3. 中斷恢復與安全鎖

- lock 必須記錄 PID、session、backend 與建立時間。
- 只有確認 owner 已結束且超過 stale 門檻，才可回收 lock。
- `APPLYING`／`RENDERING` 中斷時先 read-back，再進 `REVIEW_REQUIRED`；禁止盲目重試。
- 加入 crash、MCP disconnect、read-back mismatch 測試。

### 4. XMP fallback 與範例

- 只輸出已支援的 global develop keys。
- 以 `wx` 原子建立 XMP，拒絕覆寫既有 sidecar。
- 提供 `examples/sample-intent.json` 與 `examples/current-settings.json`；不在 repository 內散布未授權 RAW。
- Codex skill 只負責 handoff，所有 workflow 邏輯仍走 CLI。

### v0.1 gate

以下全部完成後才標記 v0.1：

1. 乾淨 clone 的 CI 全綠。
2. 至少一張非關鍵照片完成 Lightroom E2E。
3. 至少一次人工 render 檢查完成並留下紀錄。
4. 中斷後可安全恢復或明確轉人工 review。
5. XMP fallback、文件與範例可由非作者照 README 執行。

## v0.2：Closed-loop Editing

建議順序：

1. 增加 `EVALUATING`、`REFINING`、`ACCEPTED` 狀態與版本化 `EvaluationResult`。
2. 將 `render_preview` 定義成 session-only artifact：固定尺寸、hash、iteration、清理規則，不能污染交付資料夾。
3. 建立 iteration controller：每輪從最新 read-back 計算 delta，預設最多三輪。
4. 每輪建立 checkpoint；rollback 的語義必須明確是 checkpoint-based recovery，不能把它寫成 Lightroom true undo。
5. 加入 stall detection、成本／耗時／render 次數統計，以及人工升級原因。
6. 以 15–20 張涵蓋不同光線的非關鍵照片做 mock + 真實檢查，保留 evaluator rationale。

### v0.2 exit gate

每次執行都能可靠落在 `ACCEPTED` 或 `REVIEW_REQUIRED`；沒有 silent retry；中斷可恢復；成本與迭代次數可追蹤；人工檢查確認結果不是只靠語意上合理的文字。

## v0.3：Culling、Clustering、Full-shoot

只有 v0.2 穩定後才開始批次：

1. 建立 shoot manifest，批量配對 RAW／preview；模糊配對一律 `review`，不猜測。
2. 先做 read-only duplicate／burst grouping，再做 culling recommendation。
3. `select`／`keep`／`reject`／`review` 先是建議；寫入 Lightroom rating、label、keyword 必須另有明確批准。
4. 依場景／光線分群，讓使用者可以覆寫 representative。
5. 只從已接受的 representative 向同 cluster 傳播安全的 global parameters。
6. 每張照片都是獨立 job；Lightroom mutation 維持序列化，單張失敗不影響其他照片。
7. 產生 pairing、cluster、culling、成功、失敗、待 review、成本的 session report。
8. 以數百張真實 shoot 做 dry-run、故障注入、重啟與 resume 測試。

### v0.3 exit gate

一組數百張照片可產生結構化 shortlist 與 representative edits；模糊配對不會被自動猜測；中斷後已完成 job 不會重複 mutation；來源照片與既有 sidecar 不被修改。

## 暫不納入 v0.1–v0.3

Style Memory、大型桌面 UI、多 provider、更多 RAW editor backend、雲端服務與 plugin marketplace。先讓單張安全、閉環可衡量、批次可恢復，再擴充這些能力。
